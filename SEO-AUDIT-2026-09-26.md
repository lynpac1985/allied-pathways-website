## CRITICAL — the most important finding this week

**The `.htaccess` fixes from last week only work on the bare homepage URL `/`. Every real content page bypasses them entirely.** Confirmed independently by 3 separate agents (technical, sitemap, SXO) plus my own manual verification.

```
https://www.alliedpathways.com.au/            → HSTS ✓, security headers ✓, redirect ✓
https://www.alliedpathways.com.au/about.html  → none of the above, old cache headers
https://alliedpathways.com.au/about.html      → 200, no redirect to www
http://alliedpathways.com.au/about.html       → 200, fully unencrypted, no HTTPS redirect
```

**Root cause:** SiteGround's nginx layer serves any request matching a real on-disk file directly, bypassing the Apache/`.htaccess` layer entirely. Only the bare `/` (directory-index) and genuine 404s (no matching file) ever reach Apache — which is exactly why 404 handling works perfectly but nothing else does.

**This cannot be fixed with another `.htaccess` edit.** It needs a host-level fix:
- Site Tools → Domain → your domain → **HTTPS Enforce** (handles the protocol/www redirect at the nginx layer)
- A SiteGround support ticket may be needed to get custom security headers applied at the nginx layer for static file hits

**Do not mark this closed** until re-verified with `curl -sI https://alliedpathways.com.au/about.html` returning a 301, not 200.
